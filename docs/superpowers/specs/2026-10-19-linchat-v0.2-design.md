# LinChat v0.2 — Desktop AI Hub

**Date:** 2026-10-19
**Status:** Approved design (pending implementation plan)

## Summary

LinChat grows from a single-shot OpenAI-compatible GTK palette into a desktop AI
hub while keeping its minimal borderless-palette identity:

1. **Multi-provider LLM layer** — thin `requests`-only clients for OpenAI (and
   every OpenAI-compatible endpoint), Anthropic, Google Gemini, and Ollama,
   with streaming and tool/function calling.
2. **Desktop tools** — slash commands and LLM tool use for shell execution,
   app launching, Steam/game-library search, file search/read, clipboard, and
   screenshots, gated by an approve/deny bar.
3. **Agent bridges** — installed CLI agents (opencode, claude-code, codex,
   gemini/antigravity, pi, crush) appear as providers; prompts run headless
   and stream output back into linchat.
4. **Packaging** — v0.2.0 release published to AUR as `linchat-gtk` via CI,
   with the existing workflow bugs fixed.

**Out of scope for v0.2:** conversation history persistence, settings GUI,
official vendor SDKs, non-Linux platforms.

## Decisions (from brainstorming)

| Decision | Choice |
|---|---|
| Execution model | Both: slash commands for direct use AND LLM tool use behind an approval UI |
| Providers | All major hosted + local models (Ollama etc.) + auto-discovery from env vars |
| Agent interaction | Agents as providers (headless run, stream output back) |
| Desktop tools | Shell exec, app launch, game search (Steam/Heroic/Lutris/Bottles), files + clipboard + screenshots |
| UI | Enhanced palette: streaming, in-session multi-turn, Ctrl+P switcher, approval bar, slash autocomplete. No history persistence, no settings GUI |
| Provider implementation | **Approach A: thin HTTP clients** (`requests` + hand-rolled SSE). No LiteLLM, no vendor SDKs |
| Config | Stay INI/`configparser`; auto-migrate old `[API]` section |

Rationale for thin clients: near-zero new dependencies (everything remains in
official Arch repos — critical for AUR), fast cold start, full control of the
streaming/tool-call event pipeline.

## Architecture

The single-file `linchat.py` becomes a package. The CLI entry point stays
`linchat` (thin wrapper script).

```
linchat.py              # thin entry point: parse args, import linchat.app, run
linchat/
  __init__.py           # __version__ = "0.2.0"
  app.py                # Gtk window, keybindings, palette lifecycle, agentic loop
  config.py             # config load/save, migration, env discovery
  slash.py              # slash-command parser + autocomplete model
  providers/
    __init__.py
    base.py             # Provider protocol, event types, SSE helpers
    registry.py         # assembles providers: config + env + agents + model lists
    openai_compat.py    # OpenAI + any compat base_url (Groq, OpenRouter, DeepSeek,
                        #   Mistral, xAI, LM Studio, llama.cpp, vLLM, ...)
    anthropic.py        # native Messages API, streaming, tool use
    gemini.py           # native generateContent API, streaming, function declarations
    ollama.py           # native /api/chat streaming + tools, /api/tags model list
    agents.py           # CLI agents as providers (subprocess, data-driven defs)
  tools/
    __init__.py         # tool registry
    base.py             # Tool protocol, risk levels, approval policy
    shell.py            # /run        -> LLM tool shell.run      (approval: ask)
    apps.py             # /open       -> LLM tool apps.launch    (approval: ask)
    games.py            # /steam /games -> LLM tool games.search (read-only, auto;
                        #   launching a found game goes through apps.launch)
    files.py            # /find /read -> LLM tools files.search, files.read (auto)
    clipboard.py        # /clip       -> LLM tool clipboard.read (auto)
    screenshot.py       # /snap       (user-invoked only, not an LLM tool)
  ui/
    __init__.py
    chat_view.py        # streaming markdown renderer on TextView tags
    approval.py         # approve/deny bar widget
    switcher.py         # Ctrl+P provider->model fuzzy popup
tests/
  test_sse.py           # SSE/NDJSON line parsers with recorded fixture streams
  test_payloads.py      # request payload + tool-call decode per provider
  test_slash.py         # slash parser, autocomplete filtering
  test_desktop_files.py # .desktop parsing, fuzzy match
  test_vdf.py           # Steam VDF parsing, library enumeration
  test_config.py        # discovery, migration, precedence (config > env > keyring)
  test_app_smoke.py     # xvfb UI smoke test
```

### Event model

Providers expose one method:

```python
def stream(self, messages: list[Message], tools: list[ToolSpec]) -> Iterator[Event]
```

Events (dataclasses in `providers/base.py`):
- `TextDelta(str)` — append to the streaming buffer
- `ToolCall(id, name, args_json)` — request a desktop action
- `Usage(input_tokens, output_tokens)` — footer stats
- `Done(reason)` — `stop` | `tool_calls` | `max_hops` | `denied`
- `ErrorEvent(message)` — user-presentable error

### Agentic loop (app.py)

1. User submits prompt → appended to conversation as user message.
2. Active provider `.stream()` runs on a worker thread; events marshal to GTK
   via `GLib.idle_add` (existing pattern).
3. `ToolCall` pauses the stream, shows the approval bar:
   - **Approve (Enter)** — tool executes on the worker thread, result is
     appended as a tool-result message, provider resumes.
   - **Deny (Esc)** — a "user denied" result is appended so the model can
     adjust.
4. Loop capped at `General.max_tool_hops` (default 8).

Agent providers stream text only; they run their own tools internally and do
not participate in the linchat tool loop.

### Threading

All network/subprocess work happens on daemon threads. The GTK main thread
never blocks; `GLib.idle_add` is the only UI mutation path (existing pattern
in linchat.py today).

## Providers

### openai_compat.py

One client class used by every OpenAI-compatible provider:

- Endpoint: `{base_url}/chat/completions`, `Authorization: Bearer <key>`.
- Streaming: `stream: true`, hand-rolled SSE parsing (`data:` lines,
  `[DONE]` sentinel), incremental tool-call argument assembly (deltas carry
  `index`-ordered argument fragments).
- Tools: OpenAI `tools`/`tool_calls` JSON schema format.
- `list_models()`: GET `{base_url}/models`.

### anthropic.py

- Endpoint: `POST https://api.anthropic.com/v1/messages`, `x-api-key` +
  `anthropic-version` headers.
- Streaming: SSE with typed events (`content_block_delta`,
  `content_block_start` with `tool_use`, `message_delta` usage).
- Tools: Anthropic `tools` schema; tool results as user-turn `tool_result`
  content blocks.
- `list_models()`: GET `/v1/models`.

### gemini.py

- Endpoint: `POST .../v1beta/models/{model}:streamGenerateContent?alt=sse`.
- Streaming: SSE; text parts and `functionCall` parts arrive as JSON chunks.
- Tools: `functionDeclarations`; results returned via `functionResponse` parts.
- `list_models()`: GET `/v1beta/models`.
- Image input: `inlineData` parts.

### ollama.py

- Native API (not the compat shim) for full tool support: `POST /api/chat`
  with `stream: true` → NDJSON lines (not SSE).
- `list_models()`: GET `/api/tags`.
- Image input: `images` (base64) field.
- `base_url` defaults to `http://localhost:11434` (honors `OLLAMA_HOST`).

### Auto-discovery (config.py + registry.py)

Environment variables auto-register providers when present (no config needed):

| Env var | Provider |
|---|---|
| `OPENAI_API_KEY` | openai |
| `ANTHROPIC_API_KEY` | anthropic |
| `GEMINI_API_KEY` or `GOOGLE_API_KEY` | gemini |
| `GROQ_API_KEY` | groq (openai-compat) |
| `OPENROUTER_API_KEY` | openrouter (openai-compat) |
| `XAI_API_KEY` | xai (openai-compat) |
| `DEEPSEEK_API_KEY` | deepseek (openai-compat) |
| `MISTRAL_API_KEY` | mistral (openai-compat) |
| `OLLAMA_HOST` or reachable `http://localhost:11434` | ollama |

Precedence for API keys: `[provider:X] api_key` in config > env var >
`keyring` (if the optional `keyring` package is importable) > disabled.

Config entries always win over env discovery (a `[provider:groq]` section
overrides the env-registered one). Model lists come from provider
`list_models()` where available, falling back to a static default.

### agents.py — CLI agents as providers

Data-driven definitions; each has `name`, `detect` (PATH check), `cmd`
(template with `{prompt}`), and an output mode:

| Agent | Binary | Headless invocation (v1 target, verified during impl) |
|---|---|---|
| opencode | `opencode` | `opencode run {prompt}` |
| claude-code | `claude` | `claude -p {prompt} --output-format stream-json` (JSON events → text) |
| codex | `codex` | `codex exec {prompt}` |
| gemini / antigravity | `gemini` | `gemini -p {prompt}` |
| pi | `pi` | `pi {prompt}` |
| crush | `crush` | `crush {prompt}` |

- Exact flags are verified against each installed CLI during implementation;
  `[Agents] <name>_args` in config overrides the default argument template so
  nothing is hardcoded-wrong for long. `[Agents] disabled` hides agents.
- stdout streams back line-by-line as `TextDelta` events; exit code and
  stderr surface in the footer. 10-minute timeout.
- Agent responses end with a footer hint: "open in terminal" — Enter opens
  the user's terminal emulator (`$TERMINAL -e "<agent cmd>"`, falling back to
  gnome-terminal/kitty/alacritty/xterm detection) for interactive follow-up.

## Tools layer

Each tool class exposes: JSON-schema definition (`spec`), `run(args) -> str`,
risk level, approval policy, and its slash binding. Tools registry in
`tools/__init__.py`.

### /run — shell (approval: ask)

- Executes via `subprocess.run(cmd, shell=True, capture_output=True,
  timeout=30)` in the worker thread; output = stdout + stderr (labeled),
  truncated to 10KB. Timeout and non-zero exits are reported as text results
  so the LLM can react.

### /open — apps (approval: ask)

- Parses `.desktop` files from `~/.local/share/applications` and
  `/usr/share/applications` (cached, mtime-refreshed): `Name`, `Exec`,
  `Icon`, `Terminal`, categories. Fuzzy-matches the query against names
  (case/diacritics-insensitive substring + prefix scoring). Launches with
  field codes (`%f %u %U %f` etc.) stripped, `Gio.AppInfo`-style detachment
  (`subprocess.Popen` with `start_new_session=True`), Terminal=true entries
  wrapped in the detected terminal emulator.
- LLM tool `apps.launch` fuzzy-resolves the same way; approval bar shows the
  resolved `.desktop` name and final command line.

### /steam, /games — game search (read-only: auto)

- **Installed (Steam):** parse `libraryfolders.vdf` for library paths, then
  each `appmanifest_*.vdf` (`name`, `appid`, `StateFlags` for installed
  state). Steam dir discovery: `~/.steam/steam`, `~/.local/share/Steam`.
- **Store search:** `GET https://store.steampowered.com/api/storesearch/?term=<q>&l=en&cc=US`
  (JSON; title, id, price, tiny image URL rendered as text).
- `/steam <q>` = installed first (marked `installed`), then store results.
- **Heroic/Lutris/Bottles** (`/games`): best-effort reads — Heroic
  `~/.config/heroic/**/*library*` JSON; Lutris `~/.local/share/lutris/games`
  (sqlite `games.db` via stdlib `sqlite3`, fallback to rpgs JSON); Bottles
  `~/.local/share/bottles/bottles/*.yml` via a minimal line-parser (no yaml
  dep) reading Name entries. Missing sources degrade gracefully.
- Launching a found game routes through `apps.launch` approval.

### /find, /read — files (auto)

- `/find`: `locate -d <db>` if available, else `fd`, else `find $HOME
  -maxdepth 6`; results capped at 50, directories and files labeled.
- `/read`: text files only, ≤100KB, non-text (NUL byte or decode failure)
  rejected with a clear message. Paths must exist; no symlink-escape checks
  (single-user tool, same trust level as a shell).

### /clip — clipboard (auto)

- Reads `Gdk.Clipboard`/`Gtk.Clipboard` text (and image → PNG bytes if
  image-capable). `/clip` inserts content into the prompt context; the LLM
  tool returns it as text.

### /snap — screenshot (user-invoked, not an LLM tool)

- Region capture: Wayland → `grim -g "$(slurp)"`; X11 → `import` (ImageMagick)
  or `gnome-screenshot -a`. `Tools.screenshot_cmd = auto|grim|import|
  gnome-screenshot`. Full-screen fallback if region tools missing.
- Captured PNG attaches to the *next* prompt as an image part for
  vision-capable providers (OpenAI `image_url`, Anthropic `image` base64
  block, Gemini `inlineData`, Ollama `images`). Non-vision providers get a
  notice. Image is not persisted to disk.

### Approval policies

`[Tools] shell = ask|always|never`, `[Tools] launch = ask|always|never`.
`ask` (default) shows the approval bar; `always` skips it; `never` disables
the tool entirely (slash command replies "disabled in config"). Read-only
tools (games.search, files.search/read, clipboard.read) never prompt.

## UI (enhanced palette)

Same borderless, always-on-top, draggable floating window; theming via
existing `[Colors]`/`[UI]` config untouched. Additions:

- **Streaming markdown render** — `chat_view.py` renders incoming text deltas
  into the response TextView incrementally with existing tags: headings
  (h1–h3), code blocks (monospace `code` tag with background), inline code,
  bold, italic, bullet/numbered lists. Pipeline: `markdown` lib (already a
  dependency, currently unused) converts completed blocks to HTML; a small
  stdlib `html.parser`-based tagger maps elements to TextView tags. During a
  stream, in-flight text renders as plain text until the block completes.
- **Multi-turn in session** — conversation list persists while the window is
  open. Prompts and answers render as alternating blocks (prompt dimmed).
  ↑/↓ recalls previous prompts into the input. Esc once clears the input;
  Esc again clears the conversation and collapses the window back to
  input-only height.
- **Ctrl+P switcher** — fuzzy popup over the palette: provider list → model
  list (from `list_models()` / `/api/tags` / agent names), filtered as you
  type, Enter selects, Esc cancels. Active provider shown in the footer.
- **Slash autocomplete** — typing `/` at input start pops a filtered list of
  commands with one-line descriptions; Tab completes; Up/Down navigate.
- **Approval bar** — appears between input and response: full command or
  resolved action, `Approve (Enter)` / `Deny (Esc)` buttons.
- **Footer** — per-answer line: provider/model, latency, token usage when the
  provider reports it; agent answers add the "open in terminal (Enter)" hint.

## Config

`~/.config/linchat/config.ini`, INI via `configparser`. On first v0.2 run:
existing file is backed up to `config.ini.v1.bak`; `[API]` migrates to
`[provider:openai]` (endpoint → `base_url`, api_key, model); `[Colors]`,
`[UI]` copied verbatim.

```ini
[General]
default_provider =            ; empty = first discovered provider
max_tool_hops = 8
request_timeout = 60

[provider:openai]             ; section name = display name
type = openai                 ; openai | openai-compat | anthropic | gemini | ollama
api_key =                     ; empty = env var, then keyring
base_url =                    ; empty = official endpoint
model =                       ; empty = provider default

[provider:ollama]
type = ollama
base_url = http://localhost:11434

[Tools]
shell = ask
launch = ask
screenshot_cmd = auto         ; auto | grim | import | gnome-screenshot

[Agents]
disabled =                    ; comma-separated names to hide
; <name>_args = run           ; override an agent's argument template
```

Env-only users need no config file at all.

## Testing

- `pytest` unit tests (see tree): SSE/NDJSON parsers against recorded fixture
  streams per provider; tool-call payload encode/decode per provider format;
  slash parser; `.desktop` parser and fuzzy matching; Steam VDF parser;
  config discovery/migration/precedence; approval-policy gating.
- Network-facing tests are mocked by monkeypatching `requests` with recorded
  response fixtures (no extra test deps, no live keys in CI). A separate
  `make test-live` runs a manual checklist against real endpoints (not CI).
- UI smoke test under `xvfb-run` constructs the window, simulates a query
  against a fake provider, and asserts the response view renders.

## Error handling

- Provider HTTP errors surface as `ErrorEvent` with status + trimmed body
  (never the API key); shown in-response, non-fatal.
- Agent binary present but fails at runtime: stderr + exit code shown in the
  response area with the invocation line.
- Tool failures (timeout, non-zero exit, missing file) return as textual tool
  results so the model can recover; slash invocations print the same to the
  response view.
- Missing optional tools (`grim`, `slurp`, `locate`, ...) degrade with a
  message naming the missing binary and suggesting the fallback.
- Ollama unreachable → provider omitted from switcher with a footnote.
